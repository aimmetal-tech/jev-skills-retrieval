# Jev Skills Retrieval 开发

先读项目根目录 `AGENTS.md`，以当前源码为准。修改职责、入口、数据流、命令或路径时，同步其中的树和图。本 Skill 记录本项目易踩坑的决策，不提供额外的真实调用、恢复或发布授权。

## 按任务定位

- 路由、生命周期、技能选择：读根目录 `docs/architecture.md`，再沿 `src/pi-adapter.ts` → `selection.ts` → `router.ts` → `batching.ts` → `jev-client.ts` 排查。
- 凭据、配置或兼容：读根目录 `docs/configuration.md`。品牌/包名可改，旧命令、配置路径和会话类型不能跟着全局替换。
- 评测、重试或恢复：读根目录 `benchmark/README.md` 对应协议及 `docs/development.md`，确认实验身份与停止状态后再动代码。
- 结果发布：读根目录 `docs/benchmarks/2026-10-19-skillret-paused-212/README.md`，优先复用 `scripts/publish-snapshot.ts`，避免临时脚本改变分母或用量口径。

## 路由与超时的经验

1. 先区分目录准备、排队/冷却、实际网络及响应解析。没有 Jev HTTP 证据不能归因于 Jev；本地超时不能靠无限延长网络时限掩盖。
2. 每条用户请求只建一次路径身份快照；成功选择和失败回退复用它。不要做跨请求永久缓存，避免路径变更失效。
3. HTTP 400 的 `max_tokens_exceeded` 是上下文拒绝，增加时间无效。字节分批只提供保护，不证明满足 Token 上限；每批必须保持同一 state、原始问题和候选身份。
4. 全部候选评分成功后再做全局选择。失败后不使用部分结果，不把失败或缺凭据伪装成正常零命中。
5. 生产 SDK 重试为零。评测层的指数退避和共享冷却不能泄漏为日常路由默认行为。

## 模型与成本边界

Jev 用 `TYPESAFE_API_KEY` 与官方 SDK；Pi 聊天模型使用 Pi 原生账户。现有 benchmark 固定 OpenAI OAuth `gpt-6-luna` / `medium`，不能用 `LLM_BASE_URL` 代理替换账户路径。原生模型预检需要离线刷新目录，未初始化快照不能证明模型不可用。

在实际 fetch 门禁预约并持久化，尝试结算回调记账；最终 route report 不二次加总。取消或超时后未知用量仍未知。缓存只计一次，reasoning 包含在 output 中，不能额外累加。重试成功不会消除之前的未知成本。

## 持久化评测的经验

- 先读权威日志与进程状态，不能仅看 psmux pane。当前已冻结运行不自动恢复；新实验要新目录，不能混入旧结果。
- 已完成查询不可再次调度；恢复只重放本实验语义完全匹配的成功响应，不能复制另一个实验的响应充数。
- 重试次数、时间预算和未知成本跨重启保留。协议 3 的人工新恢复轮是有记录的例外，不是清空历史。
- 任务 guard 与服务故障分开：任务 turn/time limit 只暂停该任务；Pi 服务暂停影响两组，Jev 只影响插件组。IPC 超时与 HTTP 超时也必须分开。
- 不恢复或执行被隔离的 SkillsBench CVE 文件。完整任务分母保留，不能将安全阻断悄悄变成更小测试集。

## 结果与交付

先取两组共同完成的同一查询集合，再比较检索指标。用量完整子集另列，不能拿更大的原生组与较小插件组直接比较。成功读取全部 gold 只表示检索覆盖，不表示实际任务通过。

冻结原始证据保持只读。精选包只输出允许字段：query/skill ID、read/selected ID、usage、请求数、时间和恢复计数；排除密钥、账户、prompt、模型响应和本机绝对路径。保留源码版本、数据版本、输入哈希，并用原汇总验证精简转换无损。

修改后运行相关真实边界测试、`npm run check`；涉及分发运行 `npm run verify:package`，涉及精选结果运行 `npm run results:verify`。所有这些检查不需要线上模型。使用假 key、临时 home、本机假服务，不能借验证访问开发者真实凭据。

检查 diff 和暂存区，按功能闭环提交。推送或真实模型调用须符合当前任务授权；历史聊天中的一次授权不能变成 Skill 的永久许可。
